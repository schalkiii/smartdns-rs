## 补充：lookup busy 机制（性能影响澄清）
用户问 `lookup busy (multiplexer overloaded), skipping` 是否影响性能。结论：**不影响，是保护机制**。
- 源码 `src/dns_client.rs`：`NameServerGroup::lookup` 对每个上游 spawn 独立 task **并发**查询，任一上游返回有效记录即整体成功返回；busy 的上游只是跳过，不影响其他上游。
- busy 处理刻意"不重试/不重连、立即释放信号量槽位"，避免 hickory 把上游标记 Failed 触发强制重连（200ms 速率限制+TLS 握手）形成 busy→重连雪崩。
- 当前 busy 率 ~150/h（每分钟 2-3 次），已是修复后健康水平；旧方案（FuturesUnordered + 早期 cancel 产生僵尸请求占满 DnsMultiplexer 32 槽位）曾达 1057/h。a8ff30e 改用 detached task + mpsc 消除僵尸后降至 ~150/h。
- per-NameServer 并发上限为代码常量 `PER_NAMESERVER_CONCURRENCY = 12`（需改代码重编译才能调，非必需）。
