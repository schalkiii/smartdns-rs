## GitHub Actions CI 修复 + 发布 release v0.13.2

### CI 失败根因与修复（连环 3 层）
1. **web-ui 进默认特性导致 CI 编译失败**：`Cargo.toml` default 加了 `web-ui`（上一会话），而 `src/api/web_ui.rs` 的 RustEmbed `#[folder="webui/out"]` 编译期需要该目录；`.gitignore` 忽略 `webui/out` 且未入库 → CI（test/cleanliness/compatibility）编译失败。
   - 修复：`.gitignore` 移除 `webui/out`，提交 40 文件静态产物入库（commit `553193e`）。
2. **cleanliness clippy 失败**：`src/proxy.rs` `connect_udp` 的 HTTP 分支 `return Err(...)` 触发 `clippy::needless_return`（-D warnings）。改为表达式 `Err(...)`。另有 `cargo fmt` 5 文件差异（address.rs / config-parser / dns_client / dns_mw_cache / tls.rs）一并 `cargo fmt --all` 统一（commit `d70a0eb`）。
3. **release 发布 403**：`build.yml` 的 `softprops/action-gh-release` 创建 release 报 `403 Resource not accessible by integration`——workflow 未声明 `permissions: contents: write`。给 build.yml 加 workflow 级 permissions（commit `1065a7d`）。
   - 顺带增强：`build.yml` 的 `workflow_dispatch` 原本**没有 version 输入**（只有 workflow_call 有），导致无法手动指定 tag 发布；补充 `version`/`prerelease` 输入（commit `1819622`）。

### Docker job 失败修复（第 4 层 CI 问题）
- **根因**：`denied: installation not allowed to Write organization package`——`build-docker` job 推送 ghcr.io 时，`GITHUB_TOKEN` 缺少 `packages: write` 权限（workflow 级只声明了 `contents: write`）。
- **修复**（commit `faff562`，已 push）：给 `build-docker` job 单独添加 `permissions: { contents: read, packages: write }`（job 级覆盖 workflow 级，遵循最小权限）。
- **重新触发**：workflow_dispatch version=v0.13.2 → run **32258777198**（head faff562）。
  - 注意：rerun-failed-jobs 会用 run 创建时的旧 workflow 定义，permissions 修复不生效，必须重新 dispatch。
  - **PowerShell 陷阱**：`Invoke-WebRequest` 对 204 No Content 响应抛 "Object reference not set" 异常但请求实际成功 → 重试循环导致创建了 3 个重复 run（32258777198/32258793046/32258809832）。已 cancel 后两个（cancel API 的 202 同样被当异常，后续 409 证明已取消）。保留 32258777198。
  - **教训**：对 GitHub API 的 202/204 响应，不要用 Invoke-WebRequest 的 ErrorAction Stop 重试；应改用 `[HttpWebRequest]` 或预检 `$_.Exception.Response.StatusCode` 为 202/204 时视为成功。

### 本环境网络/工具备忘（重要）
- 代理 `127.0.0.1:7890`（verge-mihomo, PID 144428）对 git 的 TLS 握手不稳定：`git push` 需 `-c http.sslVerify=false`（代理 MITM 证书被拒）+ **多次重试**（1-10 次不等），偶尔成功。curl 走代理稳定；gh 走代理（Go 栈）时好时坏；PowerShell Invoke-WebRequest/Invoke-RestMethod 加 `-Proxy 'http://127.0.0.1:7890'` + `User-Agent` + 重试循环可靠。
- 本地 clippy/fmt 需直接调用工具链 bin（绕过 rustup shim，否则 "rustup could not choose a version"）：`cargo-clippy.exe clippy --profile release --target x86_64-pc-windows-msvc -- -D warnings`、`cargo-fmt.exe fmt --all -- --check`。
- GitHub API 触发 workflow：`Invoke-WebRequest POST /repos/{owner}/{repo}/actions/workflows/build.yml/dispatches`，body `{"ref":"main","inputs":{"version":"v0.13.2"}}`，Authorization Bearer（`gh auth token`），返回 204。
